7. Current Scorecard Funnelr Flow
=================================

Current browser flow:
- components/scorecard/report/UnlockPanel.tsx submits to /api/scorecard/unlock.
- On success, the browser calls /api/leads/scorecard with the permanent report URL.

Current server flow:
- app/api/leads/scorecard/route.ts validates the report URL and calls submitScorecardLeadToFunnelr().
- lib/scorecard/lead-funnelr.ts:
  1. Normalizes email.
  2. Finds existing Funnelr contact by email.
  3. Creates contact if missing.
  4. Updates existing contact if found.
  5. Attempts to update custom fields using fields from /api/v1/user/option/contactFields.
  6. Finds list by name Scorecard Leads - Sales Sequence.
  7. Directly adds contact to that list when missing.
  8. Verifies list membership.

Current Scorecard code does not:
- apply Brand: Nexubis
- apply Source: Scorecard
- apply Scorecard Request
- apply Trigger: Nexubis | Start Scorecard Sales
- directly add a sequence
- apply needsHuman tags
- use LekkeWeb tag names

The currently working production route depends on direct list-add, which triggers Funnelr automation.
Do not remove that until the tag-driven route is verified.


8. Current Cal.com Funnelr Flow
===============================

Current code:
- app/api/webhooks/cal/route.ts reads the raw body and delegates to handleCalWebhook().
- lib/cal-webhook/handler.ts defines:
  - CALL_BOOKED_TAG_NAME = Pipeline: Call Booked
  - CALL_CANCELLED_TAG_NAME = Pipeline: Call Cancelled

Current behavior:
- BOOKING_CREATED and BOOKING_RESCHEDULED:
  - verify signature
  - verify event slug
  - find or create contact
  - apply Pipeline: Call Booked
- BOOKING_CANCELLED:
  - find contact
  - remove Pipeline: Call Booked
  - if Pipeline: Call Cancelled exists, apply it

Required later:
- Change Pipeline: Call Booked to Pipeline: Nexubis | Call Booked.
- Remove Call Cancelled behavior.
- Do not start Booking Confirmation sequence.
- Let Funnelr automation own exit actions.

15. Risks and Blockers
======================

1. API writes are documented but not yet tested live.
   Mitigation: perform migration in small, inspect-after-each-write steps after approval.

2. Automation filter semantics are inferred from existing filters.
   Mitigation: use existing working LekkeWeb and Nexubis automations as templates, then test with new test contacts before code migration.

3. Scorecard Request usage count mismatch.
   Tag object says userCount 1; tag-users endpoint returned 4.
   Mitigation: re-read immediately before renaming and preserve tag ID.

4. Current code likely cannot write custom ContactProfile fields.
   It uses /api/v1/user/option/contactFields, which excludes existing custom fields.
   Mitigation: add system form-fields read support later, after Funnelr automation route is verified.

5. Scorecard Leads sequence is paused.
   Migration can preserve this state, but end-to-end sales send behavior depends on whether/when the sequence should be active.

6. Booking Confirmation is active and currently referenced by Call-booked automation.
   Mitigation: remove that action only after approval, then verify booked contact does not enter the confirmation sequence.

7. The API host is slow.
   Several read calls took 20-100 seconds. A per-contact full custom-field population scan timed out.
   Mitigation: perform writes one operation at a time with long timeouts and immediate read-back verification.
